# Deployment to FASTPANEL / Nginx

The site is statically generated by Astro and uploaded via `tar` over SSH to:

`/var/www/virtreal_ru_usr27/data/www/virtreal.ru/sedrava/`

Domain: https://sedrava.virtreal.ru

## First deployment

1. Verify in FASTPANEL that the path above is the document root for the subdomain and that the SSH user has write access.
2. Use a dedicated SSH key for deployment and an unprivileged account with write access to the site directory; do not use root.
3. In GitHub Settings → Secrets and variables → Actions, configure:
   - `SSH_HOST`: VDS hostname or IP address.
   - `SSH_USER`: account with write access to the site directory.
   - `SSH_PRIVATE_KEY`: private SSH key corresponding to an authorized public key on the VDS.
   - `SSH_KNOWN_HOSTS`: verified SSH host key line.
   - `SSH_PORT`: optional, defaults to 22.
4. Run Actions → Deploy Sedrava website → Run workflow.
5. Verify both https://sedrava.virtreal.ru/ and https://sedrava.virtreal.ru/ru/.

The workflow checks that the destination directory exists and is writable. It uses `tar` over SSH rather than `rsync`, because `rsync` is not installed on this VDS. No remote package installation is needed.

Deployment currently runs automatically on pushes to `main` and can also be started manually. It verifies bilingual 0.10.0 entry pages on the VDS after uploading. It does not delete files already on the server, and the tar extraction is not atomic; true atomic releases/rollback remain future improvements. The deploy workflow builds and checks the content itself, but it does not wait for the separate build workflow's completion.

Never commit private keys, passwords, or other server credentials.
