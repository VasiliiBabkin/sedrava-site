## Нативный режим сайта и документации

Здесь используется экспериментальный компилятор 0.11 из PR #36 и расширение документации PR #37. Их нет в опубликованном пакете 0.10.0. Установите точный checkout командой `python -m pip install '.[docs]'`: MarkdownIt 4.0.0 и Pygments 2.19.2 нужны во время сборки, а не как браузерные фреймворки.

Макет, страницы, локали, компоненты, маршруты и ресурсы описаны в [site.sdr](https://github.com/VasiliiBabkin/sedrava-site/blob/feature/sedrava-native-docs-live-examples/sedrava-next/site.sdr). Markdown хранит контент. Страницы и встроенные интерактивные примеры генерируются напрямую компилятором Sedrava без ручных изменений HTML.

## Локальный Markdown

`markdown "content/guide.md"` читает UTF-8 файл внутри корня проекта. Заголовки начинаются с h2: h1 принадлежит странице Sedrava. Списки, таблицы, блоки кода, выделение и внутренние ссылки становятся статическим HTML с Unicode-якорями и оглавлением. Сырой HTML и изображения Markdown отклоняются; изображения задаются типизированным компонентом. Один документ — до 256KiB, входные документы — до 4MiB/512 зависимостей, индекс — до 2MiB. Хеши входят в манифест.

Панели кода экранируют текст, подсвечивают Sedrava/shell/Python, показывают кнопку копирования, точный SHA и доступные номера строк. Номера aria-hidden и не попадают в копию исходника. Произвольный код при сборке не исполняется.

## Офлайн-поиск и адаптивная навигация

`search label "Поиск"` создаёт локальный индекс названий, заголовков, текста и кода двух языков. Нет API-ключа, удалённого поиска или обязательного сервера. Проверяются регистр кириллицы/латиницы, безопасные выдержки, пустой результат, стрелки и Escape. Запрос — до 160 символов, выдача — до 30 результатов.

`sidebar label "Документация":` содержит проверяемые ссылки, отмечает текущий раздел и сворачивается нативным disclosure на узком экране. Header/footer, локаль, предыдущая/следующая страница и боковое меню компонуются в `.sdr`, не зависят от жёсткого шаблонного движка.

## Настоящие примеры рядом с точным кодом

`demo "demos/counter.sdr" at "/live/counter/" label "Счётчик"` компилирует локальный WebApp в явно принадлежащий ему маршрут. Рядом с iframe показан тот же исходник с SHA и скачиванием. До 16 доверенных примеров; пересечения маршрутов и выход за корень запрещены. Для четырёх программ сравниваются байты встроенной и независимой стандартной `build webapp` сборки.

Примеры — доверенный код автора с общим origin, **не изолированный playground для недостоверного кода**. Редактора произвольного JS и секретов нет. CSP разрешает только self scripts/frames, аппаратные разрешения iframe запрещены. Нельзя обещать изоляцию при совместном same-origin/scripts. Будущему недоверенному редактору нужен отдельный origin, лимиты и разрешения.

Reload сохраняет текущий маршрут iframe. Явный reset удаляет только его данные/кеш по пути и имени, затем заменяет запись. Собственная история Back не забирает историю документа и соседних примеров. Наблюдатели отключаются на pagehide и подключаются после восстановления. Отсутствующий runtime показывает ошибку запуска, а не фиктивное рабочее демо.

## HTTP и границы размещения

Каталогу нужен настоящий объявленный JSON endpoint. Здесь он ограничен CI: на статическом хостинге показывается честная ошибка до появления согласованного сервиса. Credentials/секреты/обход CORS не генерируются. Методы, схемы, отмена, timeout и кеш проверяются настоящим loopback HTTP-сервером.

Выход — статический каталог для Nginx/FASTPANEL. `clean-urls true` включает ссылки-каталоги, сохраняя старое поведение генератора по умолчанию. Canonical/OpenGraph/sitemap используют явный dev origin, robots запрещает индексацию. [Происхождение](/ru/provenance/) фиксирует SHA, зависимости и хеши. Замена production не разрешена; staging требует отдельного принятого артефакта, backup и удалённых проверок.
